# Which laboratory-report failures should MedExtract test next?

Research and local checks, 24 November 2026. The immediate opportunity is to let a receiver check both what its software reads and what a clinician would see. A 45-institution College of American Pathologists study found 1,052 correct results among 1,059 examined. Only 732 of 1,051 examined for completeness contained all essential reporting elements. The study covered 16 laboratory tests and electronic health records then in use. Its counts describe those observations and give a reason to measure completeness independently from numeric accuracy. [Original study](https://pmc.ncbi.nlm.nih.gov/articles/PMC5513146/) · [Earlier research on FHIR projects and standards](ecosystem.md)

## Experiments on the MedExtract document

Each experiment begins with the same independently transcribed two-row source and the seven-resource EU teaching document. Each mutation changes a different representation in memory. The printed source, reviewed reference and candidate numbers are otherwise untouched. Findings in this table were measured with the original numeric v1 reference and the optional narrative API. The v0.2 typed reference now also supports the separately attested unit display, explicit absence reasons and optional decimal places. [Source](../examples/source.txt) · [Candidate](../examples/eu-teaching.document.json) · [Reviewed section manifest](../examples/eu-narrative-review.json)

| Change to the synthetic document | Structured-row check | Opt-in section check | What an implementer learns |
| --- | --- | --- | --- |
| In the results section's human-readable XHTML only, replace CRP `≤0,10` with `9,99`. | No findings | `narrative-changed` | A clinician-facing result can change while the machine-readable quantity remains faithful. |
| Keep the UCUM code `mg/L`, change only the human-readable `Quantity.unit` to `g/L`. | No findings | No findings | A display built directly from `Quantity.unit` could convey a different scale. The reviewed section and its digest did not change. |
| Keep that UCUM code, change only the display to `milligrams per litre`. | No findings | No findings | It can be legitimate for a display string to differ from its code. A test that demands character equality would produce a false alarm. |
| Change only the overall DiagnosticReport status to `corrected`. | No findings | No findings | The row reference contains Observation statuses and makes no attestation about the report's publication history. |
| Replace r01's entire quantity with `dataAbsentReason = not-performed`. | Unsupported | No findings | A receiver needs typed expected outcomes to distinguish a deliberate absence from a number. A combined result must keep the structured check's unsupported outcome visible. |

### Reproduce the human-facing check

FHIR R4 describes the subject, Composition and section narratives that make up a document's presented content. A conforming implementation can legitimately represent the same clinical text in many ways. This optional regression check covers a specific, pre-reviewed section of a fixed synthetic document. An engineer reproducing a display change can freeze the correct output and inspect future changes. [FHIR document presentation](https://hl7.org/fhir/R4/documents.html#presentation) · [FHIR Narrative](https://hl7.org/fhir/R4/narrative.html) · [Focused tests](../tests/test_narrative.py)

```python
from pathlib import Path
from medextract_fhir_lab.checker import check
from medextract_fhir_lab.jsonio import loads
from medextract_fhir_lab.narrative import check_narrative

def example(name):
    return loads((Path("examples") / name).read_bytes())

bundle = example("eu-teaching.document.json")
reference = example("reference.json")
review = example("eu-narrative-review.json")
assert check(reference, bundle) == []
assert check_narrative(bundle, review) == []
section = bundle["entry"][0]["resource"]["section"][0]["text"]
section["div"] = section["div"].replace("≤0,10", "9,99")
assert check(reference, bundle) == []
assert check_narrative(bundle, review) == [
    {"code": "narrative-changed", "field": "Composition.section.text.div"}
]
```

The manifest fixes the report identifier, results section coding and SHA-256 of the approved XHTML string encoded as UTF-8 after JSON decoding. The approved text describes the two fictional rows in the source. Fixture review here is an engineering check. A laboratory reviewer has yet to sign off. To adopt the method, an independent reviewer reads the source, checks the exact proposed text, and records its digest before testing another candidate. Calculating the expected digest from the output being scored would defeat the test.

The supported section contains plain paragraphs. Even entity spelling, whitespace or paragraph moves can change the digest. A difference invites inspection and may be a legitimate editorial change. Complex layouts, nested or ambiguous sections, document stylesheets, scripts, links, images and manual text-direction controls require another review policy. The checker never executes XHTML. Text in other sections, the section title, the subject and Composition summaries, PDF attachments and the receiver's rendered screen are outside this measurement. Its narrow scope allows an engineer to say exactly which reviewed representation changed. ## Ranked backlog for independent testing

The rank is a product judgment. A paper can demonstrate an actual laboratory workflow problem. Only a measured replay can show that this tool detects a particular failure, and external adoption still needs an independent user.

| Priority and audience | Proposed behavior and success test | Evidence and limits |
| --- | --- | --- |
| **1. Review both human and machine views.** EHR display and interface teams | Use the shipped section check. Next add an independently reviewed table with row/cell anchors, a localized unit label and two equal-unit adjacent values. Change only the displayed rows or unit and require the named discrepancy. Preserve a typography-only case and a legitimate unit synonym as controls. Count semantic contradictions and requests for human review separately. | The local mutation demonstrates the gap today. R4 separates human-readable `Quantity.unit` and machine-readable `Quantity.code`. The CAP study supports measuring display and completeness. Agreement across different renderers remains to be tested. [R4 Quantity](https://hl7.org/fhir/R4/datatypes-definitions.html#Quantity.unit) · [CAP study](https://pmc.ncbi.nlm.nih.gov/articles/PMC5513146/) |
| **2. Distinguish absence, zero and a censored number.** Extractor and LIS teams | Version the reference contract with mutually exclusive numeric, explicit absent-reason and coded-result alternatives. Begin with printed zero, a measured value with a numeric upper bound, and a visibly cancelled test explicitly marked unperformed. Match the actual source reason. A blank cell alone has unknown meaning. Require separate failures for a synthetic zero inserted on a cancelled row, a missing whole row and a bound stripped from a quantity. Include a valid numeric zero and a printed qualitative negative as controls. | `obs-6` prevents a simultaneous value and absent reason. It cannot determine which was printed. R4 represents `temp-unknown` and `not-performed` separately. Numeric-only coverage on the starter cannot establish performance for these cases. [R4 Observation constraints](https://hl7.org/fhir/R4/observation.html#invs) · [Absent-reason value set](https://hl7.org/fhir/R4/valueset-data-absent-reason.html) |
| **3. Corrections, retransmissions and clinically relevant time.** LIS/EHR integration engineers | Supply two immutable fictional reports and a separately attested replacement relationship, distinct specimen-collection and issuance times, and row-level revision history. Deliver original, correction, duplicate correction and late original. An integration harness should retain the same current value and preserve both historical versions. Include a preliminary report with an already final row, an unchanged neighboring row, and a distinct new draw with the same analyte. No sequence may be inferred from array order or from local time without a recorded offset. | A single academic center found 156 revisions among 1,278,783 reportable tests over six months. The European guide explicitly allows report and result statuses to differ. The benchmark can test software behavior per synthetic sequence. It cannot prove a clinician saw the correction. [Original correction study](https://doi.org/10.1093/ajcp/aqz036) · [EU status guidance](https://hl7.eu/fhir/laboratory/2.1.0/status-mgmt.html) · [R4 effective and issued times](https://hl7.org/fhir/R4/diagnosticreport-definitions.html#DiagnosticReport.issued) |
| **4. Preserve where a result belongs.** Laboratory middleware and HL7 v2 vendors | Extend the independently attested row key with accession, panel, specimen and draw context when available. Build a paired fictional ORU_R01/FHIR test with two panels sharing an analyte and different draws. Exchange the children or specimens while keeping every numeric value and code. The checker should name the wrong parent or specimen. A different ordering of correctly linked members should pass. A group code with no value can be a valid panel. | R4 distinguishes independent `hasMember` Observations from components that share context. The HL7 v2 mapping guide already supplies ORU_R01 and OBX maps. A 120-institution study documents actual identification errors on specimens and results. A bundle-consistency test cannot detect an upstream physical specimen swap if every identifier was copied consistently. [R4 grouping](https://hl7.org/fhir/R4/observation.html#obsgrouping) · [Published v2 maps](https://hl7.org/fhir/uv/v2mappings/STU1/artifacts.html) · [Primary identification study](https://pubmed.ncbi.nlm.nih.gov/16879009/) |
| **5. Separate exact transcription from authorized normalization.** Terminology and data engineering teams | Keep an exact transcription score and add an explicitly opted-in normalization policy. Begin with a reviewed same-property SI prefix conversion and an exact decimal scale factor. Preserve comparator direction, source unit and raw value. A wrong factor, changed specimen or unsupported mass-to-amount conversion should fail or require review; an identity conversion should pass. Record any rounding allowance and analyte-specific assumptions in the case. | UCUM defines unit syntax and semantics. LOINC additionally distinguishes component, property, timing, specimen system, scale and method. A unit library cannot supply the missing clinical context. The earlier multi-institution studies motivate this feature, and the present project has no clinically reviewed conversion table. [UCUM specification](https://ucum.org/ucum) · [LOINC term axes](https://loinc.org/kb/users-guide/major-parts-of-a-loinc-term/) · [Peer-reviewed oncology harmonization implementation](https://medinform.jmir.org/2026/1/e81254/) |

The local 0.2.0 preview now implements the explicit absent-result and exact unit-display options for structured rows. It also includes a scoped document-section review and an independent SDK example. Correction lineage, nested panel membership, qualitative results, narrative tables and reviewed unit conversions remain follow-up work. ## How to test value to a company

Give one hospital interface team and one independently maintained converter a frozen set of proposed cases with the developer's expected outcomes sealed before the run. Let each team choose its normal endpoint, FHIR server or local artifact. Record the number of cases accepted, unsupported, correctly localized, and falsely flagged after an independent review. Publish the denominators and preserve disagreements. Returning an explicit unsupported case is meaningful. Silently dropping it from reported accuracy defeats this comparison.

The relevant comparators test different boundaries. HL7's validator exercises instance and guide constraints. Inferno exercises API capabilities. NIST's historical LRI tool is a useful reference when designing HL7 v2 message tests. FHIR TestScript can describe exchange behavior, and OperationOutcome can expose machine-readable findings with issue severity and an expression. A practical integration experiment is to replay one manifest in the lab's CI, then give a receiving EHR developer the same fixture and verify that both locate the same affected row. A clinical sign-off, accreditation or legal conformity claim requires its own process.
